01

产品与任务概述

EH216-S 是亿航智能（EHang, Nasdaq: EH）自主研发的双座、纯电、无人驾驶多旋翼 eVTOL，面向城市空中旅游、城内通勤、应急消防与物流等场景。整机不设机载驾驶员，按预设航线自主飞行，由地面指挥调度系统实施监控与应急介入。完整的无人驾驶航空器系统由三部分组成：无人驾驶航空器本体、地面控制站、通信数据链路——安全分析必须覆盖"机—站—链"三位一体，而不能只看飞行器本体。

1.1 主要构型与性能参数

2 名乘员座位数（无机载飞行员）

3 套独立飞行控制系统（余度投票机制）

注：高度限制为 AGL 200 m / MSL 3000 m；以上参数依据民航局《EH216-S 型无人驾驶航空器系统专用条件》及公开产品资料整理，具体以适航数据单为准。

1.2 典型任务剖面

  • 起飞前：地面站完成系统自检、电池健康与电量核验、气象与航线核查、链路与密钥校验。
  • 爬升 / 巡航：沿预设航线自主飞行，GNSS 定位 + 多传感器姿态/速度/高度融合，地面站实时监控。
  • 下降 / 着陆：垂直下降至起降点；出现异常时 Fail-Safe 系统判断续飞或应急就近降落。
  • 降落后：断电检查、电池检修/快充、飞行数据回传与存档。

1.3 安全分析的边界

  • 系统边界：本体、地面控制站、通信链路、指挥调度系统及乘员/地面人员。
  • 环境边界：低空空域、城市/郊野起降场、气象与障碍物（含非合作目标）。
  • 生命周期：设计、生产、试验试飞、运营、维保与退役各阶段的安全闭环。
eVTOL 在城市低空、人口上方运行，即使单机失效概率极低，随着架次密度上升，绝对事故起数与对地面第三方的暴露仍需被纳入风险评估。
02

适航审定与标准框架

EH216-S 是全球首个取得中国民航局（CAAC）载人无人驾驶 eVTOL 全套适航认可的型号。由于传统有人机标准不能直接套用，CAAC 为其专门颁布了专用条件，并按专项合格审定计划推进符合性验证。理解这套审定框架，是判断其安全水平"由什么背书、覆盖到什么程度"的前提。

2.1 审定与运营资质时间线

2020-12 / 2021-01
提交 TC 申请；CAAC 适航司正式受理，为全球首个载人无人机系统 TC 审定项目。
2022-02
CAAC 颁布《EH216-S 型无人驾驶航空器系统专用条件》，覆盖结构、动力、电池配电、飞控、链路、乘员保护等专用安全要求。
2023-10-12
取得型号合格证（TC，证件号 TC0078A），型号设计被确认符合适用安全标准与适航要求。
2023-12
取得标准适航证（AC），成为全球首个获得适航证的 eVTOL 航空器。
2024-03

2025-03

2.2 安全合规所依据的方法学

参照 CAAC《民用无人驾驶航空器系统安全性分析指南》，载人无人驾驶航空器系统的安全性论证通常自上而下与自下而上相结合：

功能清单梳理本体/子系统/站/链的全部功能与任务剖面
FHA功能危害性评估，划分失效影响等级并导出安全性要求
FMEA / FTA自下而上找单点故障，自上而下建故障树验证顶事件概率
冗余与验证余度设计、软件/硬件符合性试验、试飞验证与确认
持续安全运营监控、事件报告、维保数据反馈与设计迭代
需要注意：TC/PC/AC/OC 证明的是"在审定状态、审定运行条件下满足既定安全水平"，并不等于零风险；超出包线（气象、载重、环境、改装）运行时，原有安全裕度可能下降。
03

系统安全工程分析流程

本报告按下列方法链展开。四种方法视角互补：FHA 回答"功能失效会造成什么后果"，FMEA 回答"零部件怎么坏、坏了影响谁"，FTA 回答"顶事件由哪些故障组合引发"，STPA 则从控制与反馈闭环出发，识别"控制不当/反馈缺失"等非硬件故障致险因素。

方法分析视角在 EH216-S 上的应用重点输出
FHA 功能危害性评估自上而下，按功能与任务剖面对推进、能源、飞控、导航、链路、起降等功能的全部/部分丧失、对称/不对称丧失、有无通告等组合失效定级失效状态清单、影响等级、定性/定量安全要求
FMEA 故障模式影响分析自下而上，到航线可更换单元（LRU）电机、桨叶、电池组、传感器、飞控计算机、链路模块等故障模式与严酷度、检测手段故障模式表、单点故障清单、冗余/检测建议
FTA 故障树分析自上而下，顶事件分解以"空中失控/坠机"为顶事件，分解推进、能源、飞控、链路、环境超限等分支及逻辑门最小割集、薄弱环节、概率分配依据
STPA 系统理论过程分析控制结构与反馈闭环分析地面站—链路—飞控—执行机构之间的不安全控制动作与控制缺陷（含人因、软件、信息滞后）不安全控制动作清单、约束与过程模型改进项
04

分域危险源识别

下面按系统域梳理典型危险源、失效后果与现有缓解措施；风险等级见第 05 节矩阵。

4.1 推进与动力系统

  • 单桨/单电机失效：单个旋翼推力损失，若控制律能重新分配力矩，机体可保持姿态；共轴对中上下桨同时失效则该轴推力全失。
  • 不对称推力：相邻一侧多桨失效导致升力/力矩不对称，姿态倾斜，超出可恢复范围将引发坠降。
  • 桨叶损伤/脱落：鸟击、外物撞击、疲劳裂纹导致桨叶断裂或质量不平衡，引发振动与推力偏心。
  • 电机/电调过热与退磁：高负荷、散热不足引起功率衰减或卡死。

分布式动力 + 余度吸收

4.2 能源系统（动力电池）

  • 电芯热失控：过充/过放、内短路、机械损伤、高温引发电芯过热起火或产气。
  • 热失控蔓延（TRP）：单组电池故障未被隔离，热量传导至相邻电芯/电池组，形成链式失效。
  • 电量误判：SOC 估算偏差导致提前亏电；快充循环后容量衰减与一致性劣化。
  • 高压配电短路：线束磨损、进水、碰撞后绝缘下降引发短路或拉弧。

载人 eVTOL 首要火灾风险

4.3 飞控与航电

  • 飞控计算机故障：三套余度中一套或多套失效；投票机制在一致性判断失败时可能误裁决。
  • 传感器失效/矛盾：IMU、气压高度计、GNSS、磁罗盘等漂移、卡死或数据冲突。
  • 导航退化：GNSS 遮挡/干扰（城市峡谷、多路径、欺骗）导致定位漂移或丢失。
  • 软件缺陷：控制律、故障检测与重构、自主导航算法中的逻辑错误或边界条件遗漏。

三余度飞控 + 多传感器融合

4.4 通信数据链路

  • 链路中断/延迟：遮挡、干扰、拥塞导致遥控指令与状态数据丢失或超时。
  • 恶意入侵/劫持：信号欺骗、未授权接入、数据篡改，企图接管飞行或下发错误指令。
  • 信息安全：密钥管理、加密实现、地面站与终端自身被攻破的风险。
  • 时钟/数据不同步：机—站状态不一致导致误判态势。

链路冗余 + 独立密钥加密 + 自主兜底

4.5 气动与低空气象环境

  • 风切变/突发阵风/侧风：低空、楼宇与地形诱导气流超出姿态保持能力。
  • 紊流、低温、结冰、雷雨：改变气动性能、增加载荷或影响电池/传感器工作。
  • 鸟击与漂浮物：低空鸟类、气球、塑料薄膜等非合作碰撞目标。
  • 障碍物冲突：楼宇、高压线、塔吊、其他航空器在航线或应急降落区附近。

航线/气象放行 + 感知避让

4.6 起降、地面与乘员保护

  • 起降场风险：地面人员误入桨盘范围、场地不平/松软、外来物卷入。
  • 坠地冲击与坠向第三方：迫降于水面、硬地或人口区域，乘员冲击伤害与地面第三方损害。
  • 乘员应急：无飞行员情况下乘员缺乏应急处置能力；安全带/座舱约束、出口与逃生、烟雾毒性暴露。
  • 人因与运行：遥控员监控负荷与误操作、维保差错、改装超包线、疲劳排班。

06

安全设计与冗余防护体系

6.1 冗余架构总览

EH216-S 将 IT 领域的"全备份"理念引入载人航空器：飞控、传感器、动力、电池等关键环节均采用多套备份，故障时由备份无缝接管。其安全架构可概括为"分布式动力 + 三余度飞控 + 独立电池组 + Fail-Safe 决策 + 地面兜底介入"。

动力冗余

8 轴 16 桨分布式布置，单桨失效互不牵连；控制律在故障后重新分配各桨转速与力矩，维持姿态与高度。

飞控冗余

三套独立飞控计算机协同并按投票机制裁决，配套多套传感器；实时健康监测决定续飞或应急就近降落。

能源冗余

12 组电池相互独立布置，单组内部部件失效不波及其他组；智能电池系统保障动力稳定与电量可信。

通信安全

每架航空器配独立密钥、加密传输，抵御恶意入侵；地面站与航空器实时数据交互，突发状况由中心介入施策。

应急救生

Fail-Safe 系统实时判断机体健康状态，支持自主应急就近降落；配备整机降落伞作为最终兜底手段。

运行监控

指挥调度系统集监测、调度、管理、预警、集群功能于一体，对机队状态与异常进行集中管控与事后复盘。

冗余并非越多越好：余度增加带来重量、成本、复杂度与共因失效风险。工程上需在"余度等级—重量代价—失效概率目标"之间权衡，并通过 FTA 验证冗余确实覆盖了关键单点故障。

典型失效场景推演（FTA / STPA 示例）

7.1 故障树示例：顶事件"空中失控坠机"

一级分支中间事件基本事件（示例）逻辑关系
推进失效多桨/多轴失效致推力不对称单电机卡死、桨叶脱落、电调失效、相邻轴同时故障各分支以 OR 连接进入顶事件；分支内单点与冗余失效按 AND/OR 组合，最小割集用于定位最薄弱的故障组合

分析要点：冗余设计把"单套失效"挡在最小割集之外；真正需要重点防范的是共因失效（同一批次缺陷、同一软件版本、同一环境诱因同时打击多套余度）和冗余未能覆盖的组合失效。

7.2 STPA 不安全控制动作示例

  • 未给出应有的控制：检测到电池温度异常但未触发降功率/就近降落。
  • 给出错误控制：地面站在链路抖动时误下发出错误航点或高度指令。
  • 控制时机不当：故障重构指令过晚，姿态已超出可恢复范围；或介入过早造成不必要中断。
  • 反馈缺失/滞后：地面站未及时收到异常状态，过程模型与真实态势不一致。
  • 人因过程模型偏差：遥控员对多机态势判断失误，或长期低负荷监控导致注意力下降。

7.3 三个典型场景的处置链

  • 链路中断：本机按预案自主保持/悬停 → 尝试多链路重连 → 超时未恢复则自主返航或就近降落；地面站同步记录并预警。
  • 单组电池异常：电芯/组级监测告警 → 隔离故障组、其余组继续供电 → 评估电量与位置，优先选择最近安全着陆点。
  • 单侧多桨失效：飞控识别不对称推力 → 控制律重构补偿 → 若姿态/高度可维持则就近降落，否则启动整机降落伞等兜底手段。
08

残余风险与改进建议

在现有冗余与适航约束下，仍存在难以完全消除的残余风险，需要通过设计增强、运行规则与持续安全数据闭环加以控制。

残余风险成因改进建议
电池热失控及其蔓延锂电池化学本质决定，事故后还存在迟发火与二次短路风险电芯隔热/阻焰设计、组间物理与热隔离、排气排烟通道、在线热失控早期预警；完善地面应急消防与事故后处置规程
共因失效打击多套余度同源软硬件缺陷、共同环境诱因同时影响备份通道余度通道异构设计、独立供电与布线、软件版本/缺陷隔离、强化共因失效分析与环境应力筛选
城市低空第三方风险航线下方可能存在人员与建筑，迫降空间受限航线与起降点预先避开人群密集区、划设应急降落区、完善低空感知避让与非合作目标探测、运行高度/时段约束
信息安全与自主系统信任联网节点增多，攻击面扩大；自主决策可解释性不足安全认证与密钥生命周期管理、异常指令与入侵检测、关键决策可追溯日志、持续漏洞披露与渗透测试
人因与运行差错无机载飞行员，安全高度依赖地面流程、维保与人员状态遥控员负荷与疲劳管理、标准化检查单与训练、维保差错防错、数据驱动的事件报告与整改闭环
超包线运行天气、载重、改装等超出审定状态后裕度下降明确运行包线与放行标准、改装审批与回归验证、随机状态监测与越界告警

8.1 持续安全闭环

  • 数据采集：飞行参数、电池健康、故障告警、链路质量与维保记录集中归档。
  • 分析反馈：统计故障模式与趋势，反哺 FMEA/FTA 更新、设计改进与备件策略。
  • 审定衔接：设计更改按适航要求评估符合性，重大更改回归验证后再投入运营。
